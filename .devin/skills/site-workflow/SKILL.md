# Site workflow — Сергей Зубков, Fractional CAIO

## Architecture (critical)

HTML files in the repo root and `en/` are **generated artifacts**. Never edit
them directly — changes will be overwritten on the next build.

- `_build/build_v3.py` — generates ALL RU pages (`index`, `method`, `council`,
  `cases`, `industries`, `formats`, `bureau`, `insights`, `contact`, `404`,
  `cases/*.html`), plus `sitemap.xml` and `robots.txt`. At the end it runs
  `build_en.py` via `runpy`, so one command builds everything.
- `_build/build_en.py` — generates EN pages into `en/`.
- `_build/radar.py` — SVG radar chart helper (readiness assessment).
- `_build/sample_page.py` — synthetic "Institute N" assessment (all data fictional).
- `_build/lang_detect.py` — RU/EN auto-redirect script snippet.

## Commands

```powershell
# Rebuild all pages (RU + EN + sitemap + robots)
python _build/build_v3.py

# Local preview
python -m http.server 8123
# → http://127.0.0.1:8123
```

## Editing rules

- To change page content/structure → edit `build_v3.py` (RU) and `build_en.py` (EN).
  Keep both languages in sync.
- Language rule (user-approved): RU text uses Russian terms, or Russian gloss +
  English term in parentheses — e.g. «Директор по ИИ (Chief AI Officer)»,
  «безопасная среда исполнения (safety runtime)», «на площадке заказчика (on-prem)».
  EN text uses English terms directly. Brand/product names (VIZARD, Council 7+1,
  Fractional CAIO) and standard abbreviations (LLM, ESG, ДЗЗ, AIS) stay as-is.
- Shared styles → `assets/css/style.css`; shared JS → `assets/js/main.js`.
- Verdict chips: `ИИ/green`, `Гибрид/amber`, `Без ИИ/red`, `Отложить/grey`
  (EN: `AI`, `Hybrid`, `No AI`, `Defer`).
- Design code: paper `#FAF7F2`, ink `#1C1B18`, accent green `#0F5A46`.
  No external fonts (RU availability) — serif Georgia stack, system sans, mono.
  `prefers-reduced-motion` must be respected.
- `foto/` — source photos, gitignored, never publish. Site images live in `assets/img/`.
- `SITE` placeholder in builders is `https://example.ru` — update when the real
  domain on reg.ru is known.

## Case facts convention (user-approved)

`facts` in each case dict: **first item is always `('Функции', funcs(...))`** —
bureau functions vocabulary (the `funcs()` helper + `FUNCS` dict in each
builder), NOT corporate role titles — the AI roles matrix was designed for
personal LinkedIn positioning and doesn't fit the bureau model; egip has a
free-form actual function instead. Max 2 functions per case; across all cases
the set must cover all 5 keys (caio, caito, impl, bsm, ops).
No `Отрасль`/`Industry` item — the industry is already in `tags`. The remaining
3 items are case-specific (Команда, Контур, Метрика, Этапы, …).

## Case review workflow (user convention)

Each case dict in `CASES` supports `draft=False`. The "Черновик разбора / Draft
case write-up" note is shown while `draft` is unset/true.

When the user finishes reviewing a case and writes **«Чисто»** — set
`draft=False` in that case's dict in BOTH `build_v3.py` and `build_en.py`,
rebuild, and commit.
